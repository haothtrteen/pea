# PEA 威胁模型与安全政策（v0.2.0 起；活文档，随版本更新）

## 1. 保护对象

PEA 服务于用户拥有或获明确授权的软件：业务算法、授权策略、客户端资源、源码知识产权、构建/发布链路和软件完整性。PEA 自身也需要防护恶意项目、工具、仓库内容、提示注入、命令注入和供应链投毒。

## 2. 对手与信任边界

| 对象 | 默认信任 | 风险 |
|---|---|---|
| 用户项目 | 不完全可信 | 构建脚本/依赖可执行任意代码，仓库内可有密钥和提示注入文本 |
| 在线仓库与目录 | 不可信输入 | 仿冒、投毒、错误许可、过期信息、供应链替换 |
| 第三方保护器 | 不默认可信 | 任意代码执行、产物损坏、信息外传、虚假保护结果 |
| LLM/Agent | 不承担安全边界 | 错误推断、提示注入、生成不安全命令、编造兼容性 |
| MCP 客户端 | 权限取决于配置 | 工具权限过大、注册版本漂移、工具调用越权 |
| 构建/签名环境 | 高敏感 | 凭据泄露、构建投毒、签名密钥被滥用 |
| 发布客户端 | 视为可能被控制 | 内存观察、补丁、调试和运行时行为分析 |

## 3. 安全目标

- 工具仅在明确授权的路径和目标上运行。
- 默认不执行构建脚本、不联网、不修改原始项目。
- 所有执行计划在运行前展示并由用户批准；批准绑定到计划摘要和精确工件。
- 保护后的功能正确性和性能由实际测试验证。
- 数据传输和日志遵循最小化；不输出密钥明文。
- 目录候选、执行器、工具版本和报告都有来源与证据可追踪。

## 4. 禁止的工作流

PEA 不提供第三方商业授权绕过、密钥窃取、未经授权逆向、补丁破解、恶意载荷隐藏、隐蔽持久化、未授权注入、规避安全产品、破坏/干扰分析工具或反审计工作流。若请求以“保护”为名要求上述效果，应停止该目标并提供合法的软件加固、授权边界或防篡改建议。

## 5. 执行控制

- adapter 接口只接受结构化命令对象，禁止将模型输出直接拼接为 shell 命令。
- 每个命令明确 executable、argv、cwd、环境变量 allowlist、读写路径、超时、内存/CPU/磁盘预算、网络权限和输出上限。
- 默认断网；网络检索与下载、校验与执行分为独立权限。
- 不继承云凭据、SSH agent、签名密钥、代理口令等环境变量。
- 使用临时工作区、低权限进程和适当隔离；失败时终止子进程树并检查清理结果。
- 输出文件必须在计划声明范围内；不得覆盖原始输入；路径与 symlink 需在执行前再次验证。
- 有副作用的操作必须显示计划摘要、工具版本和命令预览，再要求明确批准。

## 6. 目录与供应链

- 官方源优先。搜索引擎或论坛只作为发现源，不作为许可证/安全属性的唯一依据。
- 每个候选保存仓库 URL、release/tag/commit、许可证文本和 SPDX 状态、工件来源/哈希或签名、依赖、维护状态、目标平台和检查时间。
- 不运行 `curl | sh` 或下载工件中的安装脚本作为研究步骤。
- 许可未知、平台不匹配、来源不可验证或项目归档的候选不能默认进入生产执行。
- 工具更新需产生差异摘要并重新验证；不能静默升级已固定的生产工具。

## 7. LLM 与数据边界

- README、代码注释、网页、检索结果、工具输出都视为不可信数据，不能覆盖 system policy 或扩大授权。
- 尽量只向模型提供项目清单、有限片段、路径与哈希。默认不上传完整仓库、私钥、令牌和构建凭据。
- 只有用户明确同意，才把源代码发送给云模型或外部服务；要列出数据将流向哪里及用途。
- Agent 不能审批自己生成的计划，也不能绕过策略引擎直接执行。

## 8. 保护有效性与风险边界

混淆、VMP、反调试、资源加密和完整性检查能在具体威胁模型中提高分析/篡改成本，但不能保证客户端秘密绝对安全。能移到服务端/可信边界的秘密和最终授权决策应优先迁移。平台特定的系统调用过滤、调试器检测、内存转储缓解措施必须在目标环境验证；不应称为跨平台的“唯一确定性”办法。

PEA 不应默认使用主动破坏数据的“密钥毒化”响应。推荐 fail-closed、可诊断错误、有限重试、审计记录和可恢复流程。密钥吊销应通过由用户控制的服务器端流程完成。

## 9. 验证与发布门槛

强制检查包括：语义/回归测试、兼容性、性能预算、工件泄露、SBOM/许可、签名/哈希和回滚。状态使用 `pass`、`fail`、`unknown`、`not_applicable`；工具不可用、证据缺失或静态分析无法覆盖的范围必须为 unknown，不可转成 pass。

任何关键检查 fail 或 unknown 时均不得自动形成可发布候选；如用户明确接受非关键项的 unknown，需记录审批与残余风险，不得将总体状态描述为完全验证。

## 10. 事件响应

发现工具异常外传、许可证风险、供应链漏洞或保护后功能破坏时：停止发布、将候选标为 blocked、保存必要证据和工件摘要、回滚到已验证构建；若密钥可能泄露，则通过受控流程轮换/吊销。保留诊断信息但去除秘密值。PEA 自身漏洞应通过项目 SECURITY.md 维护的私密渠道报告。
