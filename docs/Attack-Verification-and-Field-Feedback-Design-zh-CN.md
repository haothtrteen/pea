# PEA 第三环设计：实测攻击验证与战场反馈回路

**日期：** 2026-10-14 · **性质：** 设计冻结（**已落地 0.5.0**，落地清单见 §5 与本文落地记录） · **状态来源：** 本轮战略讨论的收敛

## 0. 定位：北极星与三环

PEA 的北极星一句话：**REA 让"理解程序"变成一句话，PEA 让"证明防护"变成一句话。**

那句话展开后必然是三环，缺一不可：

| 环 | 内容 | 0.4.0 状态 |
| --- | --- | --- |
| 理解 | 只读扫描 → 暴露面 + 分层 | ✅ 七个只读域 + L2 真实字节层 |
| 决策 | 计划 + 攻击自测设计 + 审批路径 | ✅ planner / attacksim / intake / M4 令牌 |
| 证明 | 实测攻击自己、量化成本上升、证据入账 | 🟡 **本文档冻结其设计** |

防御比攻击多的两个检查点（改动前批准、效果事后证明）不是 PEA 比 REA 慢——是防御的本质：分析失败廉价（错答案重跑即可），加固失败致命（静默毁产物）。没有这两个检查点的"一句话加固"就是又一个混淆器壳子。

## 1. 核心决策：REA 作为自测 oracle，不内置攻击

**决策**：攻击工具链不进 PEA。用户自己拉取 REA（用户与 REA 之间自行适用 REA 的许可），PEA 产出"任务简报"（§2），用户的 agent 驱动 REA 执行，结果按 PEA 的证据合同回流账本。

理由（与既有纪律同构）：

1. **许可与供应链零风险**——PEA 不打包 REA 的任何字节。这与 REA 自己的做法对称：REA 对 Ghidra/IDA/Hopper 是检测用户已装引擎，不分发（已核实 REA 源码原句：*"REA never installs the Android SDK, an emulator, or a system image"*、*"REA neither starts nor manages them"*）。
2. **不复制会腐烂的工具清单**——语言族攻击模板本质是抄一份 REA 的工具目录，而这正是 `research_date` 反对的错误。用户拉的是当前版本的 REA，测的攻击面永远新鲜。
3. **分工正确**——工具 = REA 的；执行智能 = 用户接入的模型；方法论 + 证据 = PEA 的。

**REA 已核实事实**（引自 `references/rea/docs/adb-device-analysis.md`）：REA 通过用户自己的 `adb` 二进制（`REA_ADB_PATH`）检测并驱动已连接设备/模拟器，缺失时报 `capability_unavailable` 而不安装。因此**用户为 REA 攻击准备的环境（模拟器、adb、frida-server）与 PEA 测试台检测的环境是同一套**——两边投入共享，不重叠。

## 2. 任务简报（mission brief）合同

简报是 PEA 对"这次实弹演练"的输出物，五要素——其中三要素已有积木：

| 要素 | 来源 | 状态 |
| --- | --- | --- |
| 目标锚点 | 域扫描结果（如 dart-aot-check 检出的 blutter 锚点、native-check 检出的符号暴露） | ✅ 已有 |
| 工具族 | `catalog/rea-capability-defense-map.json`（REA 能力族 → 暴露面 → 防御映射） | ✅ 已有 |
| 环境分层 | §3 | 🆕 本设计 |
| 判据与时间预算 | attacksim 骨架（成功判据、预算、红线入 schema） | ✅ 已有 |
| 红线 | 仅自家产物；静态分析为主；动态插桩（frida 类）仅限自家沙盒设备 | ✅ 已写入对抗性自测文档 |

关键形态：**目标锚点来自对本工件的观察，不是静态工具清单**——"你的 libapp.so 存在 4 个快照锚点：尝试 Dart 逻辑恢复，成功判据 = 符号名可读，预算 90 分钟，环境 ≥ T2"。工具名由 agent 解析 REA 实时 catalog，简报引用能力族并附 `research_date` 注记。

**证据回流**：每步结果经 `evidence-record`（`tool_name` / `tool_version` / `artifact_digest` / `content_digest` / `authority` / `redacted_summary`）入账——该 schema 本来就是为记录第三方工具观察设计的；M5 的 `pea.ledger_record` 是入账口。演练前工件 digest 钉死（复用 artifact-manifest），保证"打的就是这个版本"。

## 3. 环境分层（T0–T4）

攻击者环境与开发者环境的不对称只真实存在于移动端动态段，且远小于直觉。分层如下，**环境缺失 = 命名 UNKNOWN，不是 FAIL**（复用三态语义与"provider 不可用 = 拒绝而非假成功"的域哲学）：

| 层 | 覆盖的攻击 | 开发者可达性 | 缺失时 |
| --- | --- | --- | --- |
| T0 纯静态 | 反编译 / 符号 / 字符串 / 快照恢复 | ✅ 一台普通电脑 | 不可缺（已落地） |
| T1 桌面全权限 | 桌面 / Electron / Python / Lua / JS 全部动态 | ✅ 本机即攻击者环境（权限对称） | 声明 unknown |
| T2 root 模拟器 | 移动端 hook / dump / 重打包 | ✅ 标准件（AVD Google APIs 镜像 `adb root` + frida-server ≈ root 真机的 95% 攻击类） | 声明 unknown |
| T3 root 真机 | 模拟器检测旁路等残差 | ⚠️ 有则测，无则声明 | 声明 unknown |
| T4 硬件级 | TEE / 硬件认证攻击 | ❌ 无法模拟 | 架构答案（见下） |

两条推论冻结为设计原则：

1. **源码作弊码**：攻击者的 invasive 技术（patch 二进制、剥校验、绕过模拟器检测）是给没有源码的人准备的。开发者用源码捷径**直接生产攻击者要费劲制造的状态**（如"检测已禁用"变体构建），验证 fail-safe（剥掉检测后服务端是否仍拒绝篡改请求）。模拟器检测差异、root 检测差异全部用测试变体消除——攻击者花真实成本到达的起点，开发者免费到达，预算花在真问题上。
2. **T4 残差是架构答案不是测试缺口**：模拟不了的暴露面不和攻击者打设备军备竞赛——移到服务端 + 硬件认证（planner 的服务端迁移路径即为此格）。无法测试的暴露面 = 必须离开客户端的暴露面。

**新增 `testbench.py` 环境侦察域**：对测试台（而非项目目录）跑与七个项目域同构的 `findings + coverage + unknowns`——检测 adb 设备、模拟器镜像、frida-server 可达性、docker/redroid 可用性，产出"本次可执行到 T 几"。不安装任何东西（与"REA 不装 SDK"同纪律）。

## 4. D7：战场反馈回路（renewable protection）

**触发器**：破解样本到达 = 重测事件。`research_date` 的时间维度从此有了事件源——保护证据的衰减不再是日历驱动，而是事件驱动。

### 4.1 破解包 intake（复用为主，增量极小）

破解包就是一个工件：七个域直接扫；与原版 `artifact-manifest` digest 逐字节 diff → 定位改动 → 哪条防护在哪层失效 → 入账。**机制几乎零新增。**

### 4.2 响应机制——冻结关键修正

**不往已分发的破解包推送代码。** 破解包不受你控制：剥掉加载路径则更新进不去；没剥掉则更新成为送上门的分析材料。

正确机制是**服务端移动球门**：轮换服务端挑战/协议/校验规则，只有仍保有并执行原始逻辑的客户端能应答。**破解者剥掉了什么，就轮换什么——他剥掉的正是他答不上的。** 这是真实 DRM/反作弊系统对抗存量破解的方式。

### 4.3 纠缠 vs 隐藏

"怎么隐藏动态加载器"是错的目标，三条理由冻结：

1. 正当的更新通道本该公开（App 热更资源/配置是正常功能），隐藏反而可疑且脆弱；
2. 隐藏的动态代码加载是恶意软件典型形态——杀软误报、平台政策（App Store 禁止下载可执行代码）、更新通道签名被破 = 给攻击者送 RCE；
3. 攻击者本来就在读你的代码，找到只是时间问题。

正确目标是**纠缠 + 证明**：校验路径与核心功能不可区分（剥掉即坏——通用 VMP skill 的精确用武之地，PEA 只负责验证其有效）+ 服务端只认只有真代码能生成的应答（attestation）。

### 4.4 红线与约束

- **中性失效**：服务器不再配合破解包；不触碰攻击者设备（敌对载荷 = sabotage 法律雷区）。
- **不误杀合法用户**：负向测试必须含"合法变体不受影响"（历史 kill-switch 误杀是真实事故教训）。
- **部署约束**：本机制仅对"有服务端"姿态可用；`intake` 已采集 `offline_required`，纯离线应用在计划推导时挡掉此措施。

### 4.5 职责边界

| PEA 做 | PEA 不做 |
| --- | --- |
| 破解包 intake + diff + 失效层定位 | 加载器/纠缠实现（产品措施，VMP skill 领域） |
| 响应规划（轮换什么、影响面、灰度策略） | 敌对载荷（红线） |
| 验证设计（破解版失效 + 合法版无伤的负向测试） | 隐藏技术（只验证有效性） |
| 对决史入账本 | — |

## 6. 边界（本设计不做的事）

- **不内置、不打包、不自动安装**：模拟器、REA、保护工具——同一纪律的三个对象，与 REA 自己不分发 Ghidra 对称。
- **不承诺"不可破解"**：产出是"对当前已知工具链，成本从 X → Y"的带时间戳证据，不是绝对安全声明。
- **不做敌对载荷**：响应的中性失效边界不可越。
- **不把演练覆盖说成覆盖完整**：未达环境层进账本 unknown，T4 残差用架构（服务端化）回答而非测试谎言。
