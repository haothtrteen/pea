# PEA Design Kit 更新说明：v0.2.1 → v0.2.2

日期：2026-10-13

## 本次改进

1. 更正 REA 能力分组中过于具体的 Provider 操作数表述；将固定数量改为按实际运行时工具合同和 Provider 声明审计，避免将旧版本或 fork 的数量当成上游 API。
2. 增加上游 README 所列目标家族的覆盖说明：ELF/Go 元数据、WASM/EVM、SQLite、.NET、Android/Flutter、固件、网络捕获、逻辑信号、记录式崩溃证据等；同时明确公开说明不等于所有环境可运行。
3. 扩展结构化 `rea-capability-defense-map.json`，增加构建元数据、字节码/数据库、移动端/托管工件、捕获/嵌入式证据四类映射。
4. 将每类能力的“分析器观察结果—软件暴露面—保护选项—验证证据—已知限制”保持为统一结构，便于未来由 Agent 检索和生成审计计划。
5. 版本升至 0.2.2；没有改变原型只做离线目录与计划生成、不执行第三方工具、不修改项目源代码的边界。

## 验证状态

- 当前公开 REA 文档已在线复核；此版本仍未完成 REA、ShellVMP、FDartVMP 的本地 clone、固定 commit、逐行源码审计或 fixture 复现。
- 本次构建中 15 个 JSON 文件均通过解析，8 个 JSON Schema 定义通过规范检查，目录条目及请求/计划/暴露发现/VMP 研究示例通过验证；10 条能力映射通过字段完整性检查。每个映射只表示候选检查方案，不表示相关分析能力已在本地环境验证。
- 离线规划器的 8 项单元测试通过，CLI 的 catalog/search/plan 冒烟测试通过。Word 文档导出为 11 页，并检查分页和表格布局。
- PEA 仍处于设计规格、研究评审、技能草案、JSON/MCP 合同和离线规划器原型阶段。
